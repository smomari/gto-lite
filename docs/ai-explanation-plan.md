# AI 핸드 설명 기능 계획

작성: 2026-11-06. 핸드가 끝난 결과 화면에 "AI 설명" 버튼을 두고, 누르면 우리 솔버가 계산한 결과를 AI가 받아 "GTO가 왜 이런 범위와 액션을 택했는지"를 프리플랍 → 플랍 → 턴 → 리버 순서로 설명하는 기능이다.

## 요구사항

- 리버까지 진행해 핸드가 끝나면 결과 화면(`components/PostflopBoard/HandSummarySection.tsx`)에 버튼이 나온다.
- AI는 **우리가 계산한 결과만** 근거로 설명한다. 스스로 전략을 새로 계산하거나 지어내지 않는다.
- 설명 순서: 프리플랍 → 플랍 → 턴 → 리버.
- 저렴한 모델을 쓴다.
- 사용 제한: 사용자당 하루 3회, 서비스 전체 하루 300회.

## 구조

```
결과 화면 ─(버튼)→ 클라이언트가 요약 데이터 생성
          ─POST /api/explain→ 서버: 검증 → 캐시 확인 → 사용량 확인 → AI 호출(스트리밍)
          ←── 섹션별 설명 스트리밍 ── 화면에 프리플랍/플랍/턴/리버 순서로 표시
```

### 1. 요약 데이터 (클라이언트 → 서버)

솔버 결과 전체(169핸드 × 노드 전부)는 너무 크다. 설명에 필요한 것만 추려 숫자 위주의 JSON으로 보낸다. 목표 크기는 프롬프트 3천 토큰 안팎이다.

- **공통:** 형식(토너/캐시), 유효 스택, 레이크, 좌석(히어로·빌런)과 포지션(IP/OOP)
- **프리플랍:** 액션 경로, 각 좌석 결정에서의 액션 비율(레이즈·콜·폴드 %), 대표 핸드군의 빈도(예: 페어, 수딧 에이스, 수딧 커넥터, 브로드웨이), 출처(`heuristic-approx` / `nash-shove-fold`)
- **스트리트마다 (플랍·턴·리버):**
  - 보드, 시작 팟, 남은 스택
  - 실제로 진행한 액션과 사이즈
  - 그 결정에서 범위 전체의 액션 비율(예: 체크 62%, 33% 벳 30%, 75% 벳 8%)
  - 핸드 강도군별 액션 비율(넛·강한 메이드·중간·드로·에어). 지금 범위 그리드가 가진 콤보별 전략에서 계산한다.
  - 양쪽 범위 크기(콤보 수)와 강도군 분포. 스트리트별 에쿼티는 플랍·턴에서 런아웃 계산이 무거워 넣지 않고, 결과의 쇼다운 에쿼티만 넣는다.
  - 솔버 정확도(익스플로이터빌리티 %)
- **결과:** 쇼다운/폴드, 최종 에쿼티(`CheckdownEquitySummary`)

요약은 `lib/explain/buildHandSummary.ts`(새 파일)에서 순수 함수로 만들어 테스트한다.

### 2. 서버 (`app/api/explain/route.ts`)

- **입력 검증:** 스키마를 엄격하게 검증한다. 문자열 필드는 카드·액션 라벨처럼 정해진 값만 허용한다. 자유 텍스트를 받지 않으므로 프롬프트 주입 여지가 거의 없다. 크기 상한(예: 20KB)을 둔다.
- **캐시:** 요약 데이터의 해시를 키로 생성된 설명을 저장한다. 같은 라인을 다시 요청하면 AI를 부르지 않고 저장본을 돌려준다. **캐시 적중은 사용 횟수에서 빼지 않는다.**
- **사용량 제한:** 캐시에 없을 때만 확인하고 차감한다.
- **AI 호출:** AI SDK의 `streamText`로 스트리밍한다. 사용자는 첫 섹션부터 바로 읽을 수 있다.
- **실패 처리:** AI 호출이 실패하면 차감한 횟수를 되돌린다.

### 3. 모델과 연결

- **연결:** Vercel AI Gateway + AI SDK를 쓴다. 이미 Vercel에 배포 중이라 키 관리(OIDC)와 사용량 대시보드, **예산 상한**을 그대로 쓸 수 있다. 나중에 모델을 바꿀 때도 문자열 하나만 바꾸면 된다.
- **모델:** 저렴한 소형 모델(예: Claude Haiku 5.5, `claude-haiku-5-5`)을 기본으로 한다. 가격과 정확한 모델 ID는 구현할 때 다시 확인한다.
- **출력 길이:** 최대 출력 토큰을 제한한다(예: 1,500). 스트리트마다 3~5문장 정도.
- **thinking:** Haiku 5.5는 thinking이 기본으로 켜져 있고(effort 기본 `medium`), thinking 토큰도 출력 단가로 과금된다. effort를 `low`로 두고 품질을 확인한다.

### 4. 프롬프트

- 시스템 프롬프트에 다음을 고정한다.
  - "주어진 수치만 근거로 설명하라. 수치에 없는 빈도나 EV를 만들지 말라."
  - 순서와 형식: `## 프리플랍`, `## 플랍`, `## 턴`, `## 리버` 섹션. 폴드로 끝났으면 거기까지만.
  - 설명할 개념: 범위 우위·넛 우위, 블로커, 폴라라이즈/머지, 사이즈 선택 이유, 포지션, SPR, 레이크·앤티 영향
  - 프리플랍 출처가 `heuristic-approx`이면 "근사 차트 기준"임을 밝히게 한다.
- 언어: 브라우저 언어가 한국어면 한국어, 아니면 영어로 답한다. UI는 영어지만 주 사용자가 한국어일 수 있어서다.
- 프롬프트는 `lib/explain/prompt.ts`에 두고, 대표 핸드 3~4개로 결과를 눈으로 검토하는 스크립트(`scripts/explain-sample.ts`)를 만든다.

### 5. 사용량 제한

- **저장소:** 서버 인스턴스가 여러 개라 메모리 카운터는 쓸 수 없다. Vercel Marketplace의 Upstash Redis를 쓴다(Vercel KV는 더 이상 제공되지 않음). 같은 저장소에 설명 캐시도 둔다.
- **사용자 식별:** 로그인이 없으므로 다음 둘을 함께 쓴다.
  - 서명된 익명 ID 쿠키(httpOnly, 1년)
  - IP 해시(원본 IP는 저장하지 않음)
  - 둘 중 하나라도 하루 3회를 넘으면 막는다. 쿠키를 지워도 같은 IP면 막히고, 공유 IP(학교·회사)는 쿠키로 어느 정도 구분된다. 공유 IP 오차는 감수한다.
- **카운터:** `explain:user:<id>:<날짜>`, `explain:ip:<hash>:<날짜>`, `explain:global:<날짜>`. 날짜는 한국 시간 자정 기준, 키는 48시간 뒤 자동 만료.
- **화면 표시:** 버튼 옆에 "오늘 남은 횟수 2/3"처럼 보여 준다. 전체 한도가 차면 "오늘은 마감되었습니다"로 비활성화한다.

## 제안하는 개선 (원래 요구사항에서 바꾼 점)

1. **같은 라인은 무료 재사용.** 캐시 적중은 횟수를 차감하지 않는다. 인기 있는 라인일수록 비용이 줄고, 사용자 체감 한도도 늘어난다.
2. **전체 한도는 비용 기준으로도 이중으로 건다.** 1000회 카운터와 별도로 AI Gateway에 월 예산 상한을 설정한다. 카운터 버그나 긴 응답이 있어도 비용이 상한을 넘지 않는다.
3. **봇 차단.** 버튼 요청에 Vercel BotID를 붙인다. 스크립트가 익명 ID를 바꿔 가며 전체 한도를 소진하는 것을 막는다.
4. **실패는 차감하지 않음.** AI 오류나 시간 초과가 나면 횟수를 돌려준다.
5. **중간 폴드에서도 사용 가능.** 요구사항은 리버까지지만, 플랍이나 턴에서 폴드로 끝난 핸드도 그 스트리트까지 설명하게 한다. 버튼 위치와 데이터가 같아 추가 비용이 거의 없다. 원치 않으면 리버 쇼다운에서만 버튼을 보이게 한다.

## 구현 현황 (2026-11-10, 브랜치 `feat/ai-explain`)

- **1단계 완료.** `lib/explain/buildHandSummary.ts`, `handStrength.ts`, 요청 스키마 `summarySchema.ts`(zod).
  - 강도군은 현재 보드에서 **그 결정 시점 상대 범위**에 대한 쇼다운 에쿼티로 나눈다(솔버 도구 방식). 넛 90% 이상, 강함 70~90%, 중간 45~70%, 그 아래는 다음 카드 8장 이상이 강함으로 만들어 주면 드로(리버 제외), 나머지 에어. 카드 제거 효과는 무시한다.
  - 처음에는 "가능한 모든 콤보 중 순위"로 나눴지만, 오버페어·탑페어가 전부 넛으로 잡혀(9-8-4 플랍에서 BB 3벳 범위의 27%) 바꿨다.
  - 실측(`scripts/explain-sample.mts`, 대표 핸드 3개): 요약 3.8~5.8KB, 약 1,200~1,800토큰. 클라이언트 계산 100ms 이하.
- **2단계 일부 진행 (2026-11-10, 무료 크레딧).** 무료 등급에서는 Haiku 5.5, GPT-6 Luna, Gemini 3.x를 쓸 수 없어 Gemini 2.5 Flash와 GPT-5 mini로 검토했다.
  - 두 모델 모두 수치 인용은 대체로 정확했다. 다만 결과의 범위 평균 에쿼티를 실제 승패로 쓰고, GPT-5 mini는 JSON 필드명과 어색한 용어("주식", "익비티")를 썼다. 프롬프트 v2에서 승패 서술과 필드명을 금지하고 한국어 포커 용어를 지정했다.
  - v2의 Gemini 2.5 Flash는 승패 오류가 거의 없어졌다. "heuristic-approx"를 그대로 쓰거나 데이터에 없는 보드 설명(플러시 드로 미완성)을 붙이는 경우가 가끔 남는다. 1회 약 $0.006으로 Haiku 5.5(약 $0.0015)의 4배다.
  - 결정: 무료 크레딧을 쓰는 동안 기본 모델을 Gemini 2.5 Flash(`lib/explain/model.ts`의 `EXPLAIN_MODEL`)로 둔다. 크레딧을 다 쓰면 유료 크레딧을 사서 Haiku 5.5로 바꾸고 같은 검토를 한다. 모델이 바뀌면 캐시 키도 바뀌어 예전 설명은 쓰지 않는다.
- **2단계 도구.** 프롬프트 `lib/explain/prompt.ts`, 모델 호출 `lib/explain/model.ts`(최대 출력 3,000토큰: 설명과 thinking 합계, reasoning `low`, 60초 제한). `npx tsx scripts/explain-sample.mts --model default`로 실제 출력을 본다. Gateway 키가 필요하다.
- **3단계 완료(모의 저장소로 테스트).** `app/api/explain/route.ts`와 `lib/explain/handlers.ts`.
  - GET은 오늘 남은 횟수, POST는 설명 스트리밍. 첫 글자가 나오기 전에 실패하면 502, 도중 실패는 스트림 오류. 두 경우 모두 횟수를 돌려준다. 사용자가 중간에 닫으면 이미 쓴 비용이라 돌려주지 않는다.
  - 캐시 키는 요약·언어·모델·프롬프트 버전의 해시, 30일 보관. 토큰 한도에서 잘린 응답도 저장한다.
  - Redis나 서명 비밀값이 없으면 기능이 꺼지고 화면에 버튼이 나오지 않는다.
- **4단계 완료.** `components/Explain/ExplainPanel.tsx`가 결과 화면 아래 전체 폭에 붙는다. 같은 화면에서 다른 라인으로 바꾸면 새로 시작한다.
- **5단계 완료 (2026-11-11).** BotID는 `next.config.ts`(`withBotId`)와 `instrumentation-client.ts`에 넣었다. Vercel 프로젝트에 Upstash Redis를 Marketplace로 연결하고 아래 변수를 Preview·Production에 넣었다. 미리보기 배포에서 버튼을 눌러 실제 설명이 나오는 것을 확인한 뒤 main에 병합했다.
  - `AI_GATEWAY_API_KEY`(로컬) 또는 Vercel 배포의 OIDC
  - `KV_REST_API_URL`·`KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`(Marketplace 연결 시 자동)
  - `EXPLAIN_SECRET`: 쿠키 서명과 IP 해시용 임의 문자열
  - 로컬 `next dev`는 Development 환경에 변수가 없고 Secret이라 `vercel env pull`로 받을 수 없다. `.env.local`에 직접 넣는다.
  - Gateway 예산 상한은 아직 걸지 않았다. 코드의 하루 300회 전체 한도가 비용을 막는다.
- **남은 일.** 무료 크레딧을 다 쓰면 유료 크레딧을 사서 Haiku 5.5로 바꾸고 출력을 다시 검토한다. 그때 "heuristic-approx" 노출과 없는 보드 설명도 프롬프트에서 손본다.

## 단계별 구현

1. **요약 생성:** `buildHandSummary`와 테스트. 대표 핸드 몇 개로 크기(토큰 수)를 확인한다.
2. **프롬프트 검토:** 스크립트로 실제 모델을 불러 설명 품질을 확인한다. 수치를 지어내는지 특히 본다. 이 단계에서 모델을 확정한다.
3. **API와 제한:** `/api/explain`, Upstash 연결, 사용량·캐시 로직, 테스트(제한 초과, 캐시 적중, 실패 시 복구, 잘못된 입력).
4. **화면:** 결과 화면에 버튼, 남은 횟수, 스트리밍 표시, 오류 표시. "AI 설명은 솔버 결과를 요약한 것이며 틀릴 수 있음" 안내 문구.
5. **배포 준비:** 환경 변수, AI Gateway 예산, BotID 설정. 브라우저에서 리버 쇼다운, 중간 폴드, 한도 초과를 확인한다.

## 필요한 외부 설정 (사용자 확인 필요)

- Vercel 프로젝트에 AI Gateway 활성화와 결제 수단(AI 호출 비용 발생)
- Upstash Redis를 Marketplace에서 연결(무료 플랜으로 시작 가능)
- 새 패키지 의존성: `ai`, Upstash 클라이언트, BotID
- Vercel Hobby 플랜은 비상업적 용도만 허용한다. 광고나 유료화를 붙이면 Pro로 바꿔야 한다.

## 위험

- **설명 정확도:** 소형 모델은 수치를 잘못 해석하거나 그럴듯한 이유를 지어낼 수 있다. 요약에 근거 수치를 충분히 넣고, 프롬프트에서 금지하고, 안내 문구를 둔다.
- **근사 프리플랍:** 프리플랍 차트가 근사 공식이라 "GTO가 왜 이렇게 했는지"를 설명하면 근사를 정답처럼 포장할 수 있다. 출처를 밝히게 한다.
- **비용:** 하루 1000회 상한과 예산 상한으로 묶인다. 실제 단가는 구현할 때 계산해 이 문서에 적는다.
- **개인정보:** IP는 해시로만 저장하고, 요약 데이터에는 개인 정보가 없다. 설명 캐시는 핸드 데이터만 담는다.
